## ⚠️ Обязательный шаг перед запуском: настройка Firebase

В `firebase-config.js` сейчас стоят **placeholder-значения**. Сайт откроется и меню будет видно, но наличие товаров, редактирование меню и вход в админку работать не будут, пока вы не подключите реальный Firebase-проект (создаётся через ваш Google-аккаунт — я не могу сделать это за вас).

### Как создать проект (10 минут)

1. Зайдите на **[console.firebase.google.com](https://console.firebase.google.com)** → **Add project** → назовите, например, `big-doner`.
2. В боковом меню откройте **Build → Firestore Database** → **Create database** → режим **Production mode** (правила ниже закроют доступ как надо).
3. В боковом меню откройте **Build → Authentication** → вкладка **Sign-in method** → включите **Email/Password**.
4. На главной странице проекта нажмите значок **`</>`** (Add app → Web), назовите приложение — Firebase покажет объект `firebaseConfig`. Скопируйте его и вставьте в `firebase-config.js` вместо placeholder-значений.
5. Во вкладке **Authentication → Users** добавьте пользователей вручную (Add user):
   - `admin@bigdoner.kz` — для администратора
   - `operator@bigdoner.kz` — для оператора
   (пароли задайте свои).
6. Во вкладке **Firestore Database → Data** создайте коллекцию `roles`, и в ней документ с **ID = UID пользователя** (UID виден в списке Users) для каждого аккаунта:
   - для admin-аккаунта: поле `role` = `"admin"`
   - для operator-аккаунта: поле `role` = `"operator"`
7. Во вкладке **Firestore Database → Rules** вставьте:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /status/{doc} {
      allow read: if true;
      allow write: if request.auth != null &&
        exists(/databases/$(database)/documents/roles/$(request.auth.uid));
    }
    match /menu/{doc} {
      allow read: if true;
      allow write: if request.auth != null &&
        get(/databases/$(database)/documents/roles/$(request.auth.uid)).data.role == "admin";
    }
    match /roles/{uid} {
      allow read: if request.auth != null && request.auth.uid == uid;
      allow write: if false; // роли меняются только вручную в консоли
    }
  }
}
```

8. Готово — после этого вход в `admin-h6y8v.html` и `operator-f3k9r.html` заработает, а нажатие «Инициализировать меню в базе» в админке загрузит стартовое меню в Firestore.

## Как запустить локально

```powershell
cd bigdoner
python -m http.server 8000
```

Затем `http://localhost:8000` на ПК или `http://<IP-вашего-ПК>:8000` на телефоне в той же Wi-Fi.

## Как задеплоить на Vercel

Сайт полностью статический — нужны только HTML/CSS/JS и папка `photos/`.

1. Создайте репозиторий на GitHub и запушьте содержимое папки `bigdoner/` (без папки-обёртки — `index.html` должен быть в корне репозитория).
2. Зайдите на [vercel.com](https://vercel.com) → **Add New Project** → Import репозитория.
3. Framework Preset: **Other**. Root Directory: оставьте пустым.
4. Нажмите **Deploy**. Через 30 секунд сайт будет доступен по адресу `https://<project-name>.vercel.app`.

## Как изменить меню / цены / номер

- **Цены и позиции** → после настройки Firebase удобнее всего через панель администратора (`admin-h6y8v.html`); либо напрямую в массиве `MENU_SEED` в `menu-data.js`.
- **Номер WhatsApp** → константа `PHONE` в `script.js`.
- **Доставка / часы работы** → блок `CONFIG` в начале `script.js`, а часы работы также в шапке `index.html` (`.hours`).
- **Логотип** → замените `photos/logo.png` (используется тот же файл и для сайта, и для favicon, и для админ-панелей).
- **Цвета / стиль** → CSS-переменные в начале `styles.css` (`--gold`, `--orange`, `--bg`).
